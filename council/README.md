# 火炬议会 Torchlight Council — 首版交互预览

页面：`https://torchlightskill.com/council/`

## 发布边界

- 独立目录 `council/`，**不修改主站根目录 `index.html`、CNAME、.nojekyll 或 `talos/`**。
- 纯静态 HTML / CSS / JS，适配 GitHub Pages `/council/` 子路径。
- 视觉参考：Codex Resets 的简洁信息展示，结合火炬赛季站队的竞技场视觉。
- 预览不登录、不收费、不接入火炬 AI 导师或其他已上线后端。
- 所有票数均为**明确标记的模拟数据**。选票仅保存在浏览器 `localStorage` 中；「模拟一轮追赶」仅修改当前页面的演出示例。不得把它描述为真实玩家投票人数或实时社区民意。

## 体验功能

1. SS14 开荒英雄（28 个特性）前 4/6 位动态柱状榜；支持点击站队、改选、柱高变化和排名动画。
2. 全部英雄搜索和选择，支持已审核常用简称。
3. 开荒命运机：使用 `crypto.getRandomValues` 在完整候选池中公平抽取；重抽不影响选择，确认才记录本地站队。
4. 迷城收益调整双选项、圆桌玩家呼声四选项投票预览。
5. SS14 北京时间开服倒计时，圆桌话题和开荒投票按预设时间封榜。
6. 分享链接，可指定英雄参数 `?hero=<id>` 进行页面内提示，但不会自动投票。
7. 键盘可操作的按钮和原生对话框，移动端和减少动态效果适配。

## 公开计票还未上线

GitHub Pages 不能保存跨设备共享投票。本次演示不提供公共计票 API，因此：

- 访客 A 投票不会改变访客 B 看到的数据。
- 刷新后当前浏览器选择可以恢复；模拟追赶的数字会重置。
- 不能据此计算真实访问→投票率、社群热度、官方玩家态度。

若准备正式开放投票，下一阶段需要独立后端，例如 Cloudflare Worker + D1/Redis，完成服务端身份令牌、每题单票与原子改选、幂等、限流、防刷、实时聚合与定时封榜。**不应将持久数据库密钥、投票后台凭据放在 Pages 前端。** 正式后端接入前需切换「演示数据」标签并经过真实跨设备验收。

## 静态验收

- `council/index.html` 直接打开；
- `./style.css`、`./app.js`、`./icon.svg` 均为相对路径；
- 所有按键不强制注册；投票可改选、不重复计票；
- 接受老虎机结果才改变当前选择；关闭或重抽不计票；
- 「模拟一轮追赶」生成的数字持续标注为演示；
- 手机窄屏无横向内容溢出；
- 首页和 `/talos/` 均保持不变。

## v0.5（2026-10-12）广告留白、按模块分享与专属分享页

### 页面布局

- 在 1280px 以上宽屏左右分别预留 160 × 600 的广告区域，主内容栏最大约 916px，两侧宽度独立于主内容。当前仅显示明确标识的占位，不加载广告脚本、不虚构广告商。
- 在较窄的电脑窗口/平板自动隐藏两侧广告区域并将内容居中，手机单栏、无侧边广告。未来插广告时替换 `.ad-rail` 的内容，不能挤压投票卡片或遮挡分享按钮。
- 仅修改 `council/` 与新增 `council/share/`，不修改主站首页、`/talos/`、CNAME 或既有后端。

### 分享转化流程

| 内容 | 分享入口 | 专属落地页 | 好友下一步 |
|---|---|---|---|
| 开荒榜 | 榜单「分享投票」 | `share/?kind=ranking`，已投英雄时为 `kind=hero&hero=<id>` | 选英雄 |
| 单个英雄 | 全部 28 张卡片各自的「分享」按钮 | `share/?kind=hero&hero=<manifest-id>` | 支持此英雄 / 选其他英雄 |
| 随机开荒 | 榜单「分享随机开荒玩法」、老虎机抽出后「分享抽签结果」 | `share/?kind=lottery` 或带 `hero=<manifest-id>` | 自己再抽一次 / 看被抽中的英雄 |
| 迷城争议 | 话题「分享这道投票」 | `share/?kind=maze&choice=support|oppose` | 直接选择支持或反对 |
| 圆桌提问 | 话题「分享这道投票」 | `share/?kind=roundtable&choice=<option-id>` | 直接在四个话题中选择 |

- 分享页采用同一套贴纸设计与桌面广告留白。入口可复制链接、调用设备系统分享、生成 1080×1440 的竖版 PNG 海报。图片分享请同时附带专属链接，PNG 上不包含动态二维码。
- URL 仅传候选特性/话题 ID，不附带玩家标识或凭据。好友打开后可以直接在分享页投票（本机），也能一键跳回相关模块继续体验。页面按清单 `type=hero/id=trait` 精确加载头像，不混用特性。
- **当前仍是本地演示**：卡片票数为模拟值，分享到别的手机不会使原榜单实时增长，也没有虚构分享人数、好友邀请次数或额外投票奖励。
- GitHub Pages 静态 HTML 无法按每个 URL 查询参数生成不同的 Open Graph 社交卡片标题和图片；目前外部社交软件会显示通用网站预览，用户点进后才看到对应英雄/话题。正式上线若希望动态链接预览，需有具备服务端渲染能力的边缘后端。
- 可以先测试分享点击、落地页访问、落地页选票转化。跨设备真实计票和完整裂变归因须接入后端再验收。
